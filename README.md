# Предсказание индекса селективности против вируса осповакцины

Решение задачи предсказания `SI VACV` по структуре соединения.
Метрика — MSE на исходной шкале SI.

---

## Коротко: что определяет результат в этой задаче

Три факта, которые мы установили измерениями и вокруг которых построено
всё решение.

**1. Задача сводится к десятку молекул.** В обучающей выборке 81 строка
из 320 имеет `SI = 0` (активность не измерялась). Нулевая строка вносит
в MSE всего `pred²`: при типичном прогнозе ~30 это около 900 единиц.
Зато одна молекула с `SI = 36 067` даёт `36067² = 1,3 млрд`. Практически
весь бюджет ошибки — примерно 13 высоких молекул из 597 тестовых;
всё остальное вместе влияет на доли процента.

**2. Полная метрика непригодна для сравнения моделей.** На обучающей
выборке 95% MSE определяется одним объектом, которого не берёт ни одна
модель. Сравнение по ней — это сравнение шума. Мы ведём отбор по метрике
**без самой экстремальной молекулы**, а полную приводим справочно.

**3. Селективность — отношение, а не свойство.** `SI = CC50 / IC50`.
Это объясняет, почему структурные отпечатки сами по себе недостаточны:
они описывают наличие фрагментов, а токсичность определяется
липофильностью, размером и распределением заряда по поверхности.
Добавление физико-химических дескрипторов дало самое крупное улучшение
за всю работу.

## Как запустить

```bash
pip install -r requirements.txt
python run.py                      # обучение и предсказание -> submission.csv
python run.py --cv                 # воспроизведение оценки качества
python build_database.py           # пересборка базы из сырой выгрузки
```

`--cv` проверяет **ту же конфигурацию**, что идёт в submission, включая
дополнительные обучающие данные, и печатает обе метрики. Подробные числа
по сидам сохраняются в `validation/cv_results.json`.

Текущий результат:

```
случайная     ПОЛНАЯ 4 242 418    БЕЗ ЭКСТРЕМУМА 192 282
по каркасам   ПОЛНАЯ 4 250 357    БЕЗ ЭКСТРЕМУМА 200 487
сводно        ПОЛНАЯ 4 245 054    БЕЗ ЭКСТРЕМУМА 195 006
```

**Почему полная метрика выше, чем на Kaggle.** На лидерборде мы получаем
около 1,7 млн, здесь 4,25 млн, и это не расхождение в качестве.
В обучающей выборке есть молекула с `SI = 36 067`, и она одна даёт
`36067² / 320 = 4,07 млн` из этих 4,25. В публичной части теста самое
большое значение примерно 13 376, поэтому там тот же член меньше на порядок.

Обе метрики измеряют одну модель, но каждая определяется своим предельным
объектом, и сравнивать их между собой бессмысленно. Сопоставим по смыслу
только порядок величины. Именно поэтому вся разработка велась
по метрике **без экстремума**: она устойчива и позволяет отличать
изменения модели от лотереи на одном объекте.

Нужны только два файла соревнования: `data/train_v2.csv` и `data/test.csv`.
Никакой сети, внешних баз и скачиваний финальный пайплайн не требует.

Все случайные состояния зафиксированы; два запуска на одной машине дают
побитово совпадающий результат. Версии библиотек закреплены
в `requirements.txt`.

**Время полного прогона** — около 15 минут на обычном процессоре
(десять сидов × четыре представления × три модели). Для быстрой проверки
работоспособности: `python run.py --seeds 1`, примерно полторы минуты.

## Соблюдение правил

Колонки `CC50_uM` и `IC50_uM_VACV` **физически удаляются из теста**
при загрузке (`src/data.py`, функция `load_competition`). Это не
договорённость, а проверяемое свойство кода: после загрузки тестовая
таблица содержит только `index`, `Title`, `SMILES`, `strain`, `Culture`.

Мера не формальная. В `test.csv` CC50 заполнена у 595 строк из 597,
IC50 — у 470, а целевая переменная равна их отношению: на обучающей
выборке совпадение лучше 1% у всех 237 строк, где заполнены обе, и точно
до последнего знака у половины. То есть для 468 тестовых строк ответ
вычисляется делением, и одной невнимательной строки кода хватило бы,
чтобы модель получила его незаметно для нас.

### Использование CC50/IC50 из обучающей выборки

Из **обучающей** выборки эти колонки используются как цели вспомогательных
моделей: одна учится предсказывать CC50 по структуре, вторая IC50, затем
первое делится на второе. Признаками они не являются нигде, и из теста
не читаются.

Основание — прямой ответ организаторов на наш вопрос:

> «можно предсказывать их друг на друга делить и получать CI»

Мы понимаем это как разрешение именно такой схемы: запрещено подавать
измеренные CC50 и IC50 в модель, но не запрещено предсказывать их
по структуре. Если трактовка окажется иной, блок отключается флагом:

```bash
python run.py --no-decomposition
```

В этом случае пайплайн обучается только на целевой переменной SI.
Вклад блока — около 12% устойчивой метрики (181 244 → 159 922).

Если колонок нет в train вообще (например, при проверке на очищенных
данных), блок отключается сам, и пайплайн отрабатывает без него.

## Финальный пайплайн

Вход — SMILES и разрешённые колонки `strain`, `Culture`, `Title`.

### Представления молекулы

Четыре семейства отпечатков, предсказания по ним **усредняются**,
а не объединяются в один вектор: ансамблирование представлений
работает, конкатенация отпечатков — нет (проверено трижды).

Три из четырёх учитывают стереохимию. Это не косметика: отпечаток,
не различающий эпимеры, считает разные молекулы одной. Из-за этого
модель ставила одной тестовой строке 13 053 вместо истинных 695,7 —
её плоская структура совпадает с обучающей молекулой, у которой
`SI = 36 067`. После перехода на стереочувствительные отпечатки
коэффициент Танимото между ними падает с 1,000 до 0,52–0,80,
а прогноз — до 7 193.

### Физико-химические дескрипторы

186 дескрипторов RDKit. Самый результативный блок во всей работе.
Особенно важны семейства `PEOE_VSA` и `SlogP_VSA` — распределение
частичного заряда и липофильности по площади поверхности, то есть
прямые характеристики взаимодействия с мембраной.

Это единственный случай, когда объединение признаков у нас сработало,
и объяснение связное: дескрипторы несут **другой род** информации,
а второе семейство отпечатков говорит о том же другими словами.

### Две модели предсказания, поровну

Регрессия по `log1p(SI)` и модель ожидания по интервалам (многоклассовая
задача на границах SI с последующим `E[SI] = Σ P(интервал) · представитель`).
Вторая лучше ведёт себя на хвосте распределения, первая — в основной массе.

### Целевое кодирование условий

`strain` и `Culture` кодируются средним целевым значением с OOF внутри
обучения и сглаживанием. Более дробный ключ (совместный `strain‖Culture`)
локально выглядел лучше на 5%, но ухудшил результат на отложенной
проверке — отвергнут.

### Дополнительные обучающие данные

Собранная база (`database/`) подключается как **дополнительные обучающие
строки** с весом 0,5. Молекулы, встречающиеся в тесте, выбрасываются
целиком по структуре без стереохимии — это расширение выборки, а не
подстановка ответов.

Смысл в том, что в соревновательной выборке всего 7 молекул с `SI > 1000`,
и именно их нехватка делает задачу тяжёлой; база добавляет ещё 19.
Вес меньше единицы отражает, что внешние измерения собраны из разных
методик и потому шумнее.

Замер: 215 976 → 208 598, лучше в обеих схемах. Отключается флагом
`--no-database`.

### Декомпозиция SI = CC50 / IC50

Одна вспомогательная модель учится предсказывать `CC50` по структуре,
вторая — `IC50`, затем первое делится на второе. Цели берутся только
из обучающей выборки.

Берётся смесь 50/50 с основной частью, а не чистая декомпозиция:
по сводной оценке они вровень, но чистая **хуже основной модели
на незнакомых каркасах**, а смесь лучше в обеих схемах валидации.

## Методология валидации

Оценка считается в двух схемах:

* **случайная** 5-кратная — приближает ситуацию «каркас встречался в обучении»;
* **по каркасам Мурко** — все валидационные молекулы имеют новый каркас.

В настоящем тесте каркас встречается в обучающей выборке у 66,8% молекул.
Поэтому сводная оценка взвешивается под фактический состав:

```
оценка = 0,668 × случайная + 0,332 × по каркасам
```

Правило приёмки: изменение принимается, если улучшает результат
**в обеих схемах** и имеет механизм. Улучшение в одной схеме при
ухудшении в другой считается шумом.

### Ошибка, которую мы нашли у себя

На середине работы выяснилось, что в скриптах экспериментов
`scaffold_kfold` вызывался с DataFrame вместо списка SMILES. Перебор
DataFrame в Python идёт по именам колонок, поэтому функция видела
десяток «молекул» с названиями `smiles`, `Title`, `strain` и раскладывала
их по фолдам. Валидировалось **10 строк из 320**, остальные оставались
с нулём в векторе предсказаний, и «полная scaffold-метрика» стабильно
выходила около 4 240 000 — при `mean(y²) = 4 254 705`. Мы измеряли
предсказание нуля.

Ничего не падало, потому что `len(DataFrame)` возвращает число строк
и маска получалась верного размера. Все выводы, сделанные по этой схеме
до исправления, были пересчитаны заново. В `src/splits.py` добавлена
проверка, которая падает с понятной ошибкой при передаче DataFrame.

### Независимая перепроверка кандидатов

Подбор гиперпараметров выявил конфигурацию, выигрывающую 5,8% в обеих
схемах. Перепроверка на других сидах показала, что выигрыш составляет
около двух стандартных отклонений при двенадцати испытанных вариантах,
то есть находится в пределах шума отбора. Конфигурация отклонена,
параметры оставлены прежними. Похожий ложный результат был пойман
этим же способом ранее.

### Наблюдение, которое стоит отметить отдельно

Литературный `IC50` ранжирует `SI` с AUC 0,979 — то есть как **ранжировщик**
он почти идеален. Но восстановление величины делением на предполагаемую
цитотоксичность проигрывает модели (247 471 против 184 274): цитотоксичность
слишком изменчива между методиками. Хороший порядок не означает хорошего
масштаба — это и привело к архитектуре, где величина предсказывается
моделью, а не вычисляется формулой.

## Сформированная база данных

`database/vacv_si_database.csv` — **1 213 соединений**, все с указанным DOI.
Формат:

```
SMILES, IC50_uM, IC50_type, CC50_uM, CC50_type, SI, DOI, n_publications, source
```

Пересобирается из сырой выгрузки одной командой: `python build_database.py`.
Выгрузка `data/raw/chembl_activities.csv` приложена, промежуточные файлы
не нужны.

**Источник — только ChEMBL.** PubChem мы опрашивали (скрипты
`data_collection/fetch_pubchem*.py`, `collect_all.py`), но в итоговую базу
он не вошёл: адресный сбор по идентификаторам из колонки `Title` дал
около десятка молекул, и мы не смогли надёжно подтвердить, что числовые
значения берутся из PubChem корректно. Скрипты оставлены как материал
по проведённой работе, а не как часть сборки базы.

**Одна строка — одно измерение.** `SI` вычисляется как `CC50 / IC50`
из пары, взятой **из одной публикации**, и все поля строки, включая DOI,
относятся к этой же работе. Если публикаций несколько, выбирается та,
чей SI медианный. Проверка: у всех 1 213 строк `SI` совпадает
с `CC50_uM / IC50_uM` с точностью округления.

**Типы измерений сохранены явно.** Под `IC50_uM` может стоять EC50,
под `CC50_uM` — TC50. Это близкие, но не тождественные величины,
поэтому исходный тип записан в отдельных колонках:

| колонка | состав |
|---|---|
| `IC50_type` | EC50 — 936, IC50 — 195, обе в одной работе — 82 |
| `CC50_type` | CC50 — 1122, TC50 — 91 |

Мы объединяем их сознательно: все они выражают концентрацию
полумаксимального эффекта, а публикации по противовирусным веществам
используют эти обозначения непоследовательно. Но читатель базы должен
видеть, что именно было измерено, поэтому колонки оставлены.

Качество базы проверено двумя независимыми способами:

* на пересечении с обучающей выборкой (114 молекул) корреляция log10
  с метрикой организаторов составила **0,960**;
* для тековиримата база даёт `SI = 2500`; истинное значение организаторов
  равно 2498 — расхождение **0,1%**.

Первая версия базы была забракована: она собиралась по упоминанию
осповируса в описании ассея и потому включала селективность против
герпеса, ВИЧ и цитомегаловируса. Корреляция составляла 0,242,
а число «высокоселективных» молекул было завышено в тридцать раз
(1425 против 43 настоящих).

## Ограничения решения

Говорим прямо, что модель не умеет.

**Редкие высокоселективные соединения она не предсказывает.** В обучающей
выборке всего 7 молекул с `SI > 1000`. Для соединения с истинным
`SI = 18 214` модель даёт 219. Никакая структурная модель на таких данных
этого не возьмёт: примеров такого уровня селективности в обучении нет.

**Стереохимия учтена частично.** Три представления из четырёх различают
эпимеры, `rdkfp` такой возможности не имеет. Для тестовой строки,
являющейся стереоизомером обучающей молекулы с `SI = 36 067`, модель
по-прежнему завышает прогноз (7 193 против истинных 695,7), хотя
и втрое меньше, чем до исправления. Чтобы знать, какой именно эпимер
